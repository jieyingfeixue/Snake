贪吃蛇改造规划

一、目标
把当前 STM32F107 + TFT9341 + 按键 + DAC 工程改造成一个可玩的贪吃蛇游戏，支持：
- 按键控制
- 等级
- 难度选择
- 得分统计
- 背景音乐与音效

二、总体架构
1. 主循环只负责：
- 读取按键
- 切换状态
- 刷新界面
- 处理暂停/结束

2. 蛇的移动节拍交给定时器中断，避免主循环里长延时卡顿。

3. 建议模块划分：
- game：游戏状态机、分数、等级、规则
- snake：蛇身数据、移动、碰撞、食物生成
- ui：开始界面、菜单界面、游戏界面、结束界面
- audio：背景音乐、吃食物音效、失败音效
- key：按键扫描与按键映射

三、状态机设计
建议设计以下状态：
- INIT：初始化外设
- MENU：菜单选择
- READY：开局准备/倒计时
- RUN：游戏运行
- PAUSE：暂停
- OVER：游戏结束

状态切换逻辑：
- INIT -> MENU：初始化完成后进入菜单
- MENU -> READY：按确认键开始
- READY -> RUN：倒计时结束
- RUN -> PAUSE：按暂停键
- PAUSE -> RUN：再次按暂停键
- RUN -> OVER：撞墙或撞到自己
- OVER -> MENU 或 READY：重开或返回菜单

四、数据结构建议
1. 蛇身
- 用数组保存每一节坐标
- 头部索引和长度独立维护

2. 基本变量
- score：当前得分
- level：当前等级
- speed：移动间隔
- difficulty：难度
- musicOn：背景音乐开关
- gameState：当前状态

3. 方向
- 上、下、左、右四个方向枚举
- 禁止直接反向移动

五、按键控制方案
建议把 4 个按键复用到菜单和游戏中：
- K1：上 / 菜单上移 / 重开
- K2：下 / 菜单下移 / 暂停
- K3：左 / 返回 / 参数减少
- K4：右 / 确认 / 开始

说明：
- 在游戏中，K1-K4 对应方向控制时，要保证不能立刻反向。
- 在菜单中，K1-K4 对应上下选择、左右调整和确认。

六、难度与等级规划
1. 难度建议
- 简单：初始速度慢，适合演示
- 普通：平衡体验
- 困难：初始速度快，成长更快

2. 等级增长
- 每吃到一定数量的食物升一级
- 简单模式：每 5 个食物升 1 级
- 普通模式：每 4 个食物升 1 级
- 困难模式：每 3 个食物升 1 级

3. 速度变化
- 等级越高，定时器间隔越短
- 可以设置速度下限，避免太快导致不可玩

七、得分规则
建议如下：
- 每吃 1 个食物：+10 分
- 每升 1 级：额外奖励或仅加速
- 游戏结束后显示：总分、等级、最高分

可选扩展：
- 最高分写入 Flash 或 EEPROM
- 失败后保留最高分记录

八、背景音乐与音效规划
1. 背景音乐
- 继续使用当前工程里的 DAC + DMA + TIM3 播放逻辑
- 在菜单和游戏进行时播放
- 暂停和结束时可以暂停或降低音量

2. 音效
- 吃到食物：短提示音
- 撞墙/撞自己：失败音
- 菜单确认：轻提示音

3. 注意事项
- 背景音乐和游戏节拍分离
- 不要让音乐播放阻塞蛇移动
- 音频更新尽量放在独立模块

九、界面规划
1. 启动页
- 显示标题、提示按键

2. 菜单页
- 开始游戏
- 难度选择
- 背景音乐开关
- 最高分显示

3. 游戏页
- 地图区域
- 蛇身
- 食物
- 分数
- 等级

4. 暂停页
- 显示暂停提示
- 提示继续按键

5. 结束页
- 显示最终得分
- 显示等级
- 提示重开或返回菜单

十、开发顺序建议
阶段 1：做最小可玩版本
- 保留现有初始化和屏幕驱动
- 实现蛇移动、食物生成、碰撞判断、得分显示

阶段 2：加入菜单和难度
- 添加开始菜单
- 增加难度切换
- 增加等级规则

阶段 3：加入暂停和结束界面
- 游戏暂停
- 失败结算
- 重开逻辑

阶段 4：优化音乐和音效
- 背景音乐循环
- 吃食物音效
- 失败音效
- 最高分保存

十一、实施建议
- 不要一次性大改所有文件
- 先保证“能跑起来”，再做“更好看、更好玩”
- 先把游戏逻辑独立出来，再接屏幕和按键
